# 谷子零售微信小程序 · 脱敏示例

原生微信小程序，使用 JavaScript、WXML、WXSS 开发。面向简单零售场景，包含商品浏览、分类搜索、购物车、下单、订单、快递配送、自取和店主商品管理。

**此仓库只含8个虚构商品、代码生成的抽象示例图片和测试数据。没有真实店铺、客户、商品表、商品照片、经营价格或库存。默认是本地演示模式，模拟付款不会扣款。**

## 快速运行

1. 使用微信开发者工具导入此文件夹。
2. 默认 AppID 是 `touristappid`。如果工具要求测试号，请使用自己的测试号；正式发布需要自己的小程序账号。
3. 编译运行，浏览商品并尝试加购。
4. 结算选择自取，填写测试联系人，提交并选择模拟付款。示例没有配置不足包邮门槛的邮费，所以低额快递订单不能提交。
5. 我的 → 演示店铺管理，可体验备货完成、自取码核销，或商品价格、库存和上下架管理。

示例活动使用五折、折后满69元包邮。这些只是功能示例，经营时需自行配置。

## 功能

- 紧凑首页、作品与商品分类、关键字搜索，有货商品优先展示。
- 单款直接加购，多款先选款；购物车数量限制与勾选商品的包邮差额。
- 详情大图、微信原生图片预览、收藏、价格及购买数量。
- 多地址管理、结算核价、快递或自取、订单查询与取消、收货确认。
- 自取备货、六位取货码及管理员核销。
- 店主改价、库存增减、上下架，订单商品与金额摘要。
- 简单客服入口。示例未配置真实联系方式。

## 检查

需要 Node.js 20 或更新版本，无须安装前端依赖。

```sh
npm test
npm run check
```

30项测试覆盖核价、库存、幂等提交、取消、地址快照、分页、自取、权限、支付验签、图片预览、快速加购与包邮差额。项目检查验证13个页面与图片资源，并检查前后端规则一致。云端测试使用模拟数据库，不代表真实支付已经联调。

## 目录

```text

  pages/                 12个业务页面
  gallery-demo/          示例图片分包与详情页
  data/                  虚构商品及图片映射
  utils/                 前端业务逻辑
cloudfunctions/commerce/ 云函数与微信支付接口代码
tests/                   功能、项目与公开数据检查
.env.example             仅为空值配置示例
```

## 配置自己的店铺

- 店铺名称、客服及运行模式：`miniprogram/config.js`。
- 演示商品：`miniprogram/data/products.js`；云端初始商品：`cloudfunctions/commerce/seed-products.json`。
- 活动与包邮规则：前后端各自的 `business.js`，须同步修改。
- 云端环境、管理员和支付参数：通过部署平台的服务端环境变量配置。私钥、API密钥、商户配置及真实业务资料不要放进仓库。
- 列表与详情图片分开用图，分包内图片先复制到客户端可读文件再预览。

建议在自己控制的私有部署副本中配置实际店铺资料，公开仓库始终保留示例数据。`.gitignore` 排除了表格、日志、私钥和本机配置；`tests/check-public-data.js` 会检查常见敏感内容及示例数据边界，但不能代替人工检查。

## 正式交易前

真实支付默认关闭。上线还需要自己的账号、支付商户绑定、云环境配置、真实商品售卖单位核对、配送设置及真机联调。平台订单发货管理、自动关单部署和退款状态同步尚未接入完整流程。

此项目的代码公开不等于已经可以直接收款营业。不要把演示付款当作真实交易。

## 可选持续检查

`ci/github-actions.example.yml` 提供 GitHub Actions 检查配置示例。需要启用时，可在 GitHub 网页把它添加为 `.github/workflows/check.yml`；本次上传不自动开启工作流。
